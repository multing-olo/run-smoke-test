# Run Smoke Tests

`run-smoke-tests` 是一个用于指导 AI Agent 执行冒烟测试的参考 Skill。它把“快速确认系统是否基本可用”整理成一套安全、可复用、以证据为基础的工作流程。

本 README 面向阅读和学习；Agent 的正式执行指令位于 [`SKILL.md`](SKILL.md)。

## 具体用途

这个 Skill 适合在以下场景中使用：

- 应用启动后进行基本可用性检查；
- 部署完成后验证服务是否正常；
- 检查健康接口、就绪状态和核心依赖；
- 验证一个关键的只读 API 路径；
- 验证一个低副作用的关键 UI 路径；
- 扫描启动日志或请求日志中的致命错误；
- 在发布前提供一个快速的放行判断。

它关注的是“系统是否基本可运行”，而不是证明系统已经完全正确、安全或适合生产环境。

## 不适用的范围

冒烟测试不能替代：

- 完整回归测试；
- 性能、压力或容量测试；
- 安全扫描和渗透测试；
- 数据一致性审计；
- 完整的跨浏览器或兼容性测试；
- 正式的生产发布审批。

即使冒烟测试结果为 `PASS`，也只能说明已选择的关键路径在本次测试范围内通过。

## 核心工作流程

Skill 会指导 Agent 按以下顺序工作：

1. **确定范围**：识别目标、环境、时间预算、关键路径和允许的副作用。
2. **读取项目约束**：检查 `AGENTS.md`、项目文档、清单文件、容器配置、CI 配置和现有测试。
3. **识别项目类型**：判断目标是本地应用、HTTP API、Web UI、容器项目还是已部署服务。
4. **设计最小测试集**：只选择能够代表系统基本可用性的关键检查。
5. **优先执行低风险检查**：先执行只读、低成本、可回滚且有超时限制的操作。
6. **收集并脱敏证据**：记录状态码、耗时、断言结果和短日志片段，隐藏凭据及敏感信息。
7. **清理临时资源**：只停止或删除本次测试明确创建的进程和资源。
8. **给出统一结论**：输出 `PASS`、`FAIL`、`BLOCKED` 或 `PASS WITH WARNINGS`。

## 结果含义

| 结果 | 含义 |
| --- | --- |
| `PASS` | 所有阻断性检查均通过，并且证据充分。 |
| `FAIL` | 至少一个阻断性检查已经执行并失败。 |
| `BLOCKED` | 没有观察到明确的阻断性失败，但至少一个关键检查无法执行或证据不足。 |
| `PASS WITH WARNINGS` | 所有阻断性检查通过，但仍有非阻断问题或清理警告。 |

如果同时存在阻断性失败和无法执行的检查，应优先报告 `FAIL`，并保留被阻断检查的说明。

## 支持的目标

当前设计能够覆盖：

- Node.js 项目；
- Python 项目；
- Java Maven 或 Gradle 项目；
- Dockerfile、Docker Compose 项目；
- HTTP API；
- 已部署的测试、预发布或生产环境；
- 需要浏览器能力的关键 Web UI 路径。

项目探测结果只是候选建议。项目自己的文档和明确指令始终具有更高优先级。

## 辅助脚本

这些脚本仅使用 Python 标准库。

### 识别项目类型

```bash
python3 scripts/detect_project.py <项目根目录>
```

脚本只读取常见项目文件，不执行被检测项目的代码。输出包括项目类型、框架、包管理器、启动命令候选和健康检查路径候选。

### 探测 HTTP 接口

```bash
python3 scripts/probe_http.py \
  https://example.test/health \
  --expect-status 200-299 \
  --json-field status=ok \
  --timeout 3 \
  --retries 2
```

该脚本执行只读 `GET` 请求，可以检查状态码、响应文本和 JSON 字段，并对 URL、响应内容及错误中的常见敏感值进行脱敏。

### 扫描致命日志

```bash
python3 scripts/scan_logs.py application.log
```

该脚本检查 `fatal`、`panic`、未处理异常、内存不足等常见致命信号，并对 Bearer Token、密码、API Key 等内容进行脱敏。

### 汇总测试结果

```bash
python3 scripts/normalize_results.py results.json
```

输入可以是检查数组，也可以是包含 `checks` 数组的 JSON 对象。脚本会统一状态名称，并计算最终发布判断。

辅助脚本的退出码约定如下：

- `0`：检查通过；
- `1`：检查已执行但失败；
- `2`：检查无效、无法执行或被阻断。

## 安全边界

这个 Skill 默认采用保守策略：

- 优先执行只读、可逆、范围明确的检查；
- 不绕过身份验证、MFA、CAPTCHA、权限或网络策略；
- 不在测试任务中自动修复代码、重新部署或重启生产服务；
- 不创建真实订单、付款、用户、消息或通知；
- 不输出或持久化密码、Token、Cookie、私钥和完整连接字符串；
- 不使用不明确路径执行递归删除；
- 只清理由本次测试创建且身份明确的进程和临时资源；
- 缺少授权、凭据、连接能力或安全清理方案时返回 `BLOCKED`。

## 可移植性与硬编码

目标 URL、端口、凭据、绝对路径、启动命令、测试身份和业务期望值都应在运行时提供或从目标项目中安全发现，不应写入 Skill。

仓库中出现的健康路径、状态范围、超时、错误模式和示例域名只是可移植的默认候选，可以被项目说明或明确的运行时参数覆盖。

## 与其他 Skill 协作

这个 Skill 可以把特定子任务交给其他可用 Skill，例如使用浏览器类 Skill 验证交互式 UI 路径。被调用的 Skill 只负责对应子任务；冒烟测试的范围、断言、证据、安全边界和最终结论仍由本 Skill 统一管理。

如果所需能力不存在，应采用安全替代方案，或把对应检查标记为 `BLOCKED`，而不是假设工具一定可用。
